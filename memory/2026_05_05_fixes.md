## Bug 1 — Paper 模式 heartbeat monitor 未啟用（`engine.py`）

**根因**：`engine.py` line 518 原本只在 `trading_mode == "live"` 時啟動 broker heartbeat monitor（30s timeout → 自動重連）。Paper 模式 Solace 斷線後只能靠 KbarPoller fallback + watchdog 10 分鐘後重啟。

**修復**：`if self.trading_mode in ("live", "paper")`

**影響**：2026-05-05 08:50 進場後 52 秒 Solace 斷線，broker 沒有嘗試重連，直到手動重啟才恢復。

## Bug 2 — 策略狀態持久化（`engine.py` + `position.py`）

**根因**：
- `_entry_atr`：進場時的 ATR（用於計算 trail trigger/distance）
- `_trail_best`：持倉期間最高/最低價（用於計算 trail stop）
- 這兩個值只存在策略 instance 的記憶體，重啟後歸零
- `check_exit()` fallback：`atr = self._entry_atr if self._entry_atr > 0 else snapshot.atr`
- 重啟後用當前 ATR（可能是進場 ATR 的 3~5 倍）→ trail 距離暴增 → 提前或延後出��

**修復**：
1. `position.py`：`_save_position()` 新增 `strategy_state` 欄位，`restore_positions()` 讀回到 `pos._strategy_state`
2. `engine.py`：新增 `_save_strategy_state()` / `_restore_strategy_state()` 方法
3. 存盤時機：進場後 + 每根 K ��� + tick 級節流（每 30 秒）
4. 恢復時機：`restore_positions()` 後立即呼叫 `_restore_strategy_state()`

**存盤內容**：
```json
{
  "strategy_state": {
    "entry_atr": 14.0,
    "trail_best": 40922.0,
    "breakeven_active": false,
    "scaled_out": false
  }
}
```

**2026-05-05 影響**：
- 進場 ATR=14pt，重啟後 fallback 用 snapshot.atr=53pt
- trail_trigger 從 14pt 變成 53pt，trail_dist 從 17.5pt 變成 66pt
- 結果：trail 過早觸發出場 @ 40,922（+69pt），本應持有更久

## Bug 3 — Watchdog 持倉跳過重啟���`scripts/watchdog.py`）

**根因**：三處「有持倉 → 跳過重啟」的舊保護（怕重啟丟倉），在 hard TP/SL 修復後不再需要。

**修復**：移除三處 `pos_side != "flat"` 判斷，改為無條件重啟：
1. Solace fallback > 10 分鐘
2. [Scan] 無心跳紀錄 > 12 分鐘
3. [Scan] 心跳過期 > 12 分鐘

## 系統架構：Solace 斷線恢復鏈

```
Solace 斷線
  ↓ 30s
broker heartbeat monitor 觸發 _attempt_reconnect()（3 次重��）
  ↓ 成功 → Solace 恢復，tick 正常
  ↓ 3 次失敗
KbarPoller fallback（REST snapshots 每 interval 秒）+ hard TP/SL 持續檢查
  ↓ 10 min
watchdog 偵測 fallback_active > FALLBACK_TIMEOUT → 強制重啟 server
  ↓ 重啟
持倉恢復 + 策略狀態恢復 + Solace 重新訂閱
```
