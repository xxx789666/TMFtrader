## ① 2026-05-07 — Watchdog 持倉時 TG spam（workaround，**根本修還沒做**）

**症狀**：日盤 server 進場後，TG 每分鐘發「策略心跳異常 X 分鐘無 [Scan]」警告。

**根因**：`core/engine.py:1024-1046` 設計缺陷 — 有持倉時只呼叫 `strategy.check_exit()`，**不呼叫 `strategy.on_kbar()`**，所以 `[Scan]` log 永遠不寫。但 watchdog 用 `[Scan]` 心跳當策略健康判據 → 誤判卡住 → TG 警告。

**Workaround**：`scripts/watchdog.py` 加入持倉感知：
- 從 `state["position"]` (單商品) 或 `state["instruments_data"][inst]["position"]` (多商品) 偵測 `quantity > 0`
- 若 `holding=True`：[Scan] 缺失視為已知設計缺陷，**靜音不發 TG、不重啟**
- 若 `holding=False`：照舊邏輯（警告+重啟）

**還沒做的根本修復**：`engine.py:_process_kbar` 持倉分支應該也呼叫 `on_kbar` 或至少 log 一行 `[Scan]`，讓 watchdog 看到正常心跳。修完之後 watchdog 的「靜音 workaround」可移除。
**Why:** 持倉中 [Scan] 缺失是設計而非 bug，但 watchdog 不知道，造成 spam。徹底解法在 engine.py 而非 watchdog.py。  
**How to apply:** 如果未來 watchdog log 還出現「持倉中 [Scan] 缺失（已知設計缺陷），靜音不重啟」訊息，代表還沒從根本修。要修就改 `core/engine.py:1024` 持倉分支補上 [Scan] log，然後拿掉 watchdog 的 holding 檢查邏輯。

**重要**：watchdog process 本身要 kill+restart 才會載入新 code（pythonw process 不會 hot reload .py）。最後一次 process 重啟在 2026-05-07 23:27 左右。

## ② 2026-05-11 — Dashboard 重啟/重整後進出場 markers 消失

**症狀**：http://localhost:8888/ 重整網頁或 server 重啟後，K 棒圖上的 BUY/SELL/EXIT 標示完全不見，即使當天有交易（trade list 顯示正常）。

**根因**：`dashboard/static/index.html:fetchTrades()` 只從 API 拉資料填左側 trade list（`trades.value = merged`），**沒有重建 chart 上的 `tradeMarkers` 也沒 call `candleSeries.setMarkers`**。WebSocket 即時推送的 `trade` 事件會即時 push marker，但這些只存在於前端 JS 記憶體，網頁重整就消失。

**修法**：fetchTrades 重構為：
1. 保留原始 `rawTrades` 陣列（有 entry_time + exit_time + side）
2. 為每筆已平倉 trade 產生兩個 markers：
   - 進場：多單 ↑綠箭頭 (belowBar / 'BUY')；空單 ↓紅箭頭 (aboveBar / 'SELL')
   - 出場：橘色方塊 (aboveBar / 'EXIT')
3. 還開著的持倉從 `state.instruments_data[inst].position.entry_time` 補一個進場 marker（防重複）
4. `candleSeries.setMarkers(tradeMarkers.slice().sort(...))`

**部署**：FastAPI 用 `StaticFiles` mount，**改完 HTML 不用重啟 server**，瀏覽器 `Ctrl + Shift + R` 強制重整即可。

## ④ 2026-05-11 17:30 — INITIAL_BALANCE 漏算後續交易（**反覆會發生的問題**）

**症狀**：dashboard 顯示的「可用保證金」跟 5/1 至今實際累計對不上。例如夜盤顯示 199,670，但其實已經到 203,930（漏算 +4,260）。日盤類似：.env=214,310，實際應該 222,890（漏算 +8,580）。

**根因**：paper 模式 `pm.balance` 是 in-memory，**每次 server 重啟都讀回 `.env` / `start_night.py` 的 INITIAL_BALANCE**。如果上次同步 baseline 之後又有交易，這些獲利只存在於 in-memory，下次任何重啟（watchdog 自動 / 手動 / Shioaji 連線斷重啟）就會丟失。

**這個問題會持續發生**，因為：
- 我們從 5/4 開始累積實際 P&L，但 .env 同步是手動的
- 每筆新成交需要再次手動更新 INITIAL_BALANCE 才不會在下次重啟丟失
- 過程中 server 可能重啟好幾次（watchdog / Shioaji WRONGTYPE 自癒等）

**5/11 17:30 修正值**：
- 夜盤 INITIAL_BALANCE：199670 → **203930**（補 +1,920 5/6 23:28 + +2,340 5/8 00:17）
- 日盤 INITIAL_BALANCE：214310 → **222890**（補 +6,240 5/7-8 + +2,340 5/11 早上）
- 重啟夜盤生效；日盤**不重啟**（今日 +2,340 還在 memory，重啟會丟）

**永久解法**（沒做）：讓 `pm.balance` 也持久化到磁碟，每次重啟讀回最新值。要動 `core/position.py` 加入 balance 持久化邏輯。目前每次手動同步是 workaround。
**Why:** paper 模式 `pm.balance` 不持久化是設計選擇，但每次重啟丟失累積獲利的 UX 很糟。  
**How to apply:** 下次 user 問「可用保證金不對」或「累計權益錯了」，先檢查：1) `.env` / `start_night.py` 的 INITIAL_BALANCE 2) 比對 engine log 的 `_execute_exit_inner` 完整出場清單 3) 算出真實累計，重新同步 .env + risk_state.json + 重啟。修完 `pm.balance` 持久化前，這個問題會反覆出現。

## ⑤ 2026-05-11 — 排程任務改背景執行

**症狀**：三個排程觸發時都跳出 cmd 視窗（即使 bat 內已用 `start /B pythonw` 或 `powershell -WindowStyle Hidden`，因為排程觸發的是 cmd.exe 本身）。

**修法**：用 `Set-ScheduledTask` 把三個 task 的 Execute 改成 `powershell.exe`，Argument 改成：

```
-WindowStyle Hidden -NoProfile -ExecutionPolicy Bypass -Command "& '<bat 完整路徑>'"
```

**三個 task**：
- `TMFtrader-NightORB` → `start_night_server.bat`
- `TMFtrader_DaySession` → `restart_trader.bat`
- `TMFtrader_NightSession` → `restart_trader.bat`

**重要**：`Set-ScheduledTask` 需要管理員權限，要用 `Start-Process powershell -Verb RunAs` 提權執行才會成功。沒提權會印 "Access is denied" 但 try/catch 仍可能顯示 OK（誤導）— 一定要 `Get-ScheduledTask` 驗證 Execute 欄位是否真的改成 powershell.exe。

**Why:** Windows 排程 Action 是 cmd.exe 時，無論 bat 內怎麼背景啟動，cmd 視窗本身會在 bat 執行期間（taskkill / timeout / netstat 那幾秒）顯示出來。改用 hidden PowerShell 包裝才能完全靜默。  
**How to apply:** 未來新增任何 Trading 相關排程，Action 直接用 `powershell.exe -WindowStyle Hidden -NoProfile -ExecutionPolicy Bypass -Command "& '<bat>'"`，別用 cmd.exe。
